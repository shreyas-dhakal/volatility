## Final review corrections

Two independent review findings fixed in `services/knowledge.py` with regression tests: persisted answer descriptions are now included in bounded context, plus an explicit stakeholder-answer section independent of message-history age. Approved knowledge is ordered before pending records, with omitted-count metadata when the bounded record cap is reached. Candidate SDK input tests verify that the direct UI answer survives thirty subsequent messages and seventy newer pending records.

Proposal deduplication now compares exact substantive content (title, description, payload), excluding generated lineage fields. Changed same-title proposals create new pending records with `supersedes_id`, `proposal_revision` and a prior-record snapshot in history; the old approved/rejected record stays unchanged. Identical active proposals deduplicate; rejected proposals can be reproposed. Traceability identity includes graph and business decision IDs, so a new graph import cannot return a stale mapping merely because its title matches.

Chat completeness correction: `create_change_driver` and `create_business_requirement` are registered, validated pending-only tools; system instructions proactively select them. Parameterized dispatch tests cover correct persisted kind/status, owner checks, cross-project evidence rejection and mismatched-kind rejection.

Chat tool orchestration is capped at twelve provider rounds (sequential tool calls plus final response), allowing the normal multi-record discovery journey to complete. Regression tests exercise six consecutive real tool dispatches followed by final text, and twelve tool rounds terminating with an error and no fabricated assistant completion.
